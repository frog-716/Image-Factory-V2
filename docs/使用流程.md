# 使用流程

**当前：阶段A为PARTIAL，尚未启用正式运营链路。** 原生工作流到官方DeepSeek的安全连接未核实，两款自动Prompt验收未执行。不要将旧草稿当作新AI结果。

## 阶段A的目标

运营在飞书填需求，工作流生成完整Prompt，同一行状态变为“待生成”。本轮到此停止，等待用户验收。

1. 新建一行生图任务，选择商品、渠道、三个固定图片功能之一、一个已批准的主输入素材。
2. 补一句自由想法，目标图片数量通常为3，任务状态为“待准备”。
3. 工作流读取商品事实、素材说明与可见范围，自动选取启用且匹配渠道、品类、图片功能的组件。
4. 商品与素材检查通过，才调用官方DeepSeek `deepseek-flash`。
5. 成功且结果校验通过，完整结果写入“智能提示词草稿”，状态变为“待生成”。运营在该行查看想法和Prompt，从选择素材查看原图附件。

日常不需要Terminal、启动脚本、Finder找包、ZIP、本地ID或Python拼装。原Python只保留作legacy / validation only，不是上述流程的实现证明。

## 必须先通过的检查

- 商品状态为“可用”。
- 素材允许用于生图，且关联商品与当前商品一致。
- 只有一个明确主输入商品素材，附件及可见范围明确。
- 目标图片数量为空时默认3。

失败时停止并给出运营能读懂的提示，不能让AI猜授权或商品关联。现有工作流尚未部署，可读错误提示也尚未验收。

## AI写什么

AI接收商品事实、素材事实及可见范围、禁改项、渠道、图片功能、当前相关组件和自由想法，输出明显不同的A/B/C方向，以及一份可直接复制给ChatGPT Image的中文Prompt。

差异来自场景、版式、构图、光线、色彩与视觉语言。商品禁改项优先，不改颜色或原标记，不猜未知视角、鞋底、后跟、内部、穿着角度、材质、性能和参数，不新增商品功能或认证。自由想法与事实冲突时忽略冲突部分。

## 当前接通门

已实际检查当前Base的自动化HTTP节点：提供普通请求头、公式及记录引用，没有可核实的安全连接/Secret入口；当前CLI协议也只描述文本及引用型请求头。另一个飞书产品的连接器能力不能直接算作本Base已支持。

因此没有输入或保存Key，没有创建/启用工作流，没有调用DeepSeek。只有确认原生安全连接确实可用，才交给用户本人在安全输入页填写Key；不得发送到聊天、普通表字段、日志、Prompt或GitHub。不能加本地代理绕过。
