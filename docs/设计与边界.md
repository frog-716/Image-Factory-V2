# 设计与边界

## 项目要解决什么

让鞋服电商运营在不学习复杂节点工具的情况下：
1. 选对真实商品素材；
2. 选择一个看得懂的创作做法；
3. 得到可直接交给 GPT 的生成包；
4. 从多张候选里做采用/淘汰；
5. 把结果积累成下一次可复用经验。

## 日常职责

- 飞书：商品、素材、任务、结果与反馈
- GPT 网页端：实际生图和多轮局部调整
- Codex：开发、维护、迁移、校验、分析
- 运营：创意选择、个人想法、最终图片判断

## 当前刻意不做

- 不恢复 V1 的重型 Workflow Engine
- 不恢复 Runtime / Runner 生图队列
- 不让 Codex 成为每次生图的必经主控
- 不记录完整 Prompt Iteration Log
- 不让运营理解 SHA、Run ID 等工程字段
- 不在质量尚未证明前继续堆自动化

## 关键边界

商品可见事实是硬约束；背景、构图、视觉层次是创意空间。
没有真实素材证明的商品角度、结构、参数和功能，不由模型补造。

飞书是当前任务输入、人工使用快照及反馈的权威来源；本地批准清单限定哪些实际原图可用。连接脚本实时核验后准备包，本地登记只保存真实记录ID与包版本的关联，不再维护一套竞争的业务状态。纯本地组装规则不依赖飞书传输层。

连接由运营显式运行，不使用原生事件触发或后台进程。复制任务不复制使用快照及反馈；草稿可更新，已有快照不能覆盖；真实使用时才首次确认快照。附件回填只新建反馈，不修改旧行。界面截图只用于链路验收，评价留空，不能算成图。
