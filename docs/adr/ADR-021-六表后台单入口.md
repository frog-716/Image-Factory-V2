# ADR-021 · 六张表是后台，运营只走单入口

状态：Accepted
日期：2026-10-04

## 真实反馈

阶段3技术验收通过后，用户第一次打开飞书即反馈：

> 表太多，不知道该干什么，使用逻辑搞不清楚。

这说明六表数据模型可以继续保留，但不能把六张表直接当作运营流程。

## 决策

底层仍保留六张表，不拆、不合并、不增加新业务表。

日常运营只需要理解两步：

1. `① 开始生图`
2. `② 成图反馈`

未来周度总结上线后再增加：

3. `③ 周度复盘`

商品库、素材库、提示词组件库属于资料层。运营只有在需要换商品、换素材或调整组件时才进入，不作为每天的必经步骤。

## 第一入口

复用现有“生图任务”视图，改成运营入口，视图名：

`① 从这里开始｜准备生图`

只显示完成一次生图真正需要的信息：
- 任务名称
- 商品
- 渠道
- 图片功能
- 选择素材
- 目标图片数量
- 自由补充想法
- 智能提示词草稿
- 任务状态

默认隐藏：
- 操作人
- 创建时间
- 场景
- 风格
- 所处版面
- 选择提示词组件
- 最终提示词快照

原因：保护组件已经自动组装，运营不需要先理解 17~19 个组件关系。

## 第二入口

复用现有“成图与反馈”视图，改名：

`② 回来这里选图`

只显示：
- 图片附件
- 关联任务
- 结果（采用 / 淘汰）
- 问题标签
- 喜欢标签
- 一句话备注

## 使用规则

第一次进入系统，不要求用户浏览商品库、素材库、提示词组件库或周度总结。

文档、书签和后续交接默认直接给“① 从这里开始”的深链接，不默认给 Base 根入口。

如果仅靠简化视图仍然让真实运营迷失，再评估飞书应用模式/运营首页；MVP 不提前新增第七张表或自建前端。
