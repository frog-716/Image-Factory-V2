## 一、日常操作：完成一轮三图

| 步骤 | 人做什么 | 完成信号 |
|---|---|---|
| 1. 填任务 | 先写想法，再补齐商品和获准素材 | 必需输入齐全，待准备，最终快照为空 |
| 2. 等Prompt | 查看完整草稿和商品保护信息 | 草稿完整，自动待生成 |
| 3. 网页生图 | ChatGPT独立对话上传原图＋完整Prompt | A/B/C三张独立图片，人工对照原图 |
| 4. 冻结 | 保存实际发送原文，确认后改待回传 | 最终快照与实际使用文字一致 |
| 5. 回填 | 任务按钮预建ABC，画册筛选一次，分别上传 | 三图正确、每图关联当前任务 |
| 6. 评价 | 本人逐张采用/淘汰，原因可选 | 三图齐全且评价齐全，自动已完成 |

### 1. 先写想法，最后补齐商品和素材

进入「生图任务」新建记录，使用唯一任务名。先填渠道、图片功能、目标数量和自由补充想法，再选择一个明确商品及其已批准原图。默认数量3，状态待准备，最终快照留空。输入齐全可能马上触发，先写想法可以避免这一句漏进本次生成。

| 常用输入 | 怎么填 |
|---|---|
| 任务名称 | 自己一眼能认出，保持唯一；自动完成靠唯一匹配保护 |
| 渠道 | 拼多多或天猫超市 |
| 图片功能 | 下表三选一 |
| 目标图片数量 | 当前正式三图路径使用3 |
| 自由补充想法 | 例如“克制自然的零售空间，背景浅一点，不要抢衣服主体” |
| 商品 | 本次唯一商品，状态可用 |
| 选择素材 | 同商品、允许用于生图、有附件的真实原图 |

| 图片功能 | 什么时候选 | 创意变化来自哪里 |
|---|---|---|
| 商品看清楚 | 商品要清楚、干净、信息明确 | 简洁背景、光线和留白 |
| 穿搭换环境 | 已有模特穿着图，要换环境 | 周围空间；保留衣服、人物、姿势 |
| 版式有设计感 | 原图正确，希望更像广告展示 | 背景、图形、阴影与版式；保留商品事实 |

### 2. 等完整草稿和待生成

飞书读取合格商品、获准且匹配的素材资料，以及渠道、用途、数量、用户想法；原生AI写完整中文Prompt。成功后只写「智能提示词草稿」和「待生成」。运营不用手选26组件。

确认草稿完整、有三个不同方向，商品事实与可见范围正确。AI调用失败或查不到合格商品/素材时，不手工改成待生成。重做失败时旧草稿可能仍在，不能当成本次新结果。

### 3. ChatGPT网页取得三张独立图

打开「选择素材」记录的附件，取得已批准真实原图；完整复制草稿。为这次商品新开一个ChatGPT对话，上传原图、粘贴完整Prompt并发送。无需本地包或本地Prompt程序。

要求**3张独立图片，A/B/C各一张**。一张三栏拼图、重复图或把拼图裁三份都不算。少方向时在同一对话补，例如：

> 请继续完成缺少的B方向，只输出这一张独立完整图片，不要拼图。

不为补图重新调用飞书AI。逐张对照原图检查明显变化：服装看原模特、姿势和已见衣服结构；鞋看素材颜色、原组合布局与标记，不能补未知鞋底、后跟、内部或穿着角度。保留真实A/B/C文件，用户尚未评价就不填采用/淘汰。

### 4. 冻结实际发送文字，再改待回传

生成完成后，将**实际发送给ChatGPT的完整Prompt原文**保存到「最终提示词快照」。原样使用草稿时可完整复制草稿；若发送前改过文字，保存修改后的实际原文，不能回头复制一份没用过的草稿。草稿保持原样。

读回确认一致，再手工改「待回传」。同一对话后续的补生成/微调指令与首发Prompt分开留痕，不把快照说成ChatGPT全部对话或内部提示词。已有最终快照不覆盖；明显换商品、颜色、用途或创意方向时新建任务。

### 5. 一次预建，三次上传

在待回传任务点击「三图回填 → 建立ABC反馈」。系统只在该任务没有反馈时建立三条，自动名称带A/B/C和任务名，关联当前真实任务。已有部分记录时也不继续补建或覆盖，不要反复点按钮。

进入「成图与反馈 → ③ 同任务三图｜比较与评价」，将关联任务筛选选为本任务一次。按钮不会自动跳转或替你筛选。依次打开A/B/C详情，分别上传对应独立图片，核对没串图、没关联旧任务。**上传仍是三次**，没有一次上传自动拆分三条的功能。

### 6. 先上传齐全，再由本人逐张评价

宽屏画册可并排看三张，窄屏会换行。对照三图后打开各张详情，选择「采用」或「淘汰」，可选填一句真实原因。空结果只是未评价，不是淘汰。标签不是必填，在比较视图隐藏；不硬造标签。委托代拟理由时标注来源，不能冒充本人原话。

当前已验收顺序是**三图先上传，随后评价**。最后一条评价保存后，工作流检查三图齐全、评价齐全、任务唯一且在待回传或待评价，才自动已完成。1/3、2/3不会提前完成。它是事件触发检查，不是后台定时补扫；“先评价、后上传”的完成触发未实测，遇到这种情况请维护者查日志，不要改旧反馈来凑触发。

<a id="troubleshooting"></a>
## 二、故障速查

| 看到的问题 | 先查什么 | 下一步 |
|---|---|---|
| Prompt没出现 | 商品、渠道、图片功能、素材齐全？待准备？快照为空？ | 再查商品可用、素材授权/匹配/附件；条件正确仍失败，交维护者查原生运行日志 |
| 想改一句想法 | 最终快照是否空？ | 空：改想法后重新待准备，等新草稿；非空：新建任务，保留旧快照 |
| 旧草稿在，但这轮失败 | 状态与本轮运行是否成功？ | 旧内容不等于本轮成功，不手工补待生成 |
| ChatGPT出拼图或只出部分 | 是否三张真正独立文件？ | 在同一对话逐个补缺方向；不重做飞书Prompt、不裁拼图凑数 |
| 点按钮没有新ABC | 状态待回传？该任务已有反馈吗？ | 有记录就核对已有数据；部分成功先读回，禁止盲目重建 |
| 画册显示别的任务 | 关联任务筛选是否选当前任务？ | 只替换筛选一次；不要改记录关联来迁就视图 |
| 任务没自动完成 | 正好3条？各有附件和评价？任务唯一？等待状态？ | 核对上传先于评价；仍异常由维护者查事件日志，不随意删记录或改历史 |
| 图片明显改错商品 | 原图身份、颜色与可见范围？ | 本人决定淘汰/返工，不以技术成功强行采用；不把错图回写成商品事实 |

## 三、六表与65字段参考

| 表 | 最简单理解 | 当前是否参与日常主链 | 字段数 |
|---|---|---|---:|
| 商品库 | 商品事实是什么 | 是，资料维护 | 10 |
| 素材库 | 哪些真实图片获准、能证明什么 | 是，资料维护 | 11 |
| 提示词组件库 | 积累的创作方法和规则 | 保留26组件，Composer不读取 | 8 |
| 生图任务 | 这一次要做什么 | 是，运营主要入口 | 17 |
| 成图与反馈 | 每张结果与本人判断 | 是，运营回传入口 | 7 |
| 周度总结 | 一段时间的汇总资料 | 保留，正式自动周报未部署 | 12 |
| 合计 | 六表关系保留 | 原64字段＋Stage D任务按钮1 | 65 |

商品事实、素材证据、任务和图片结果各有归属。一次任务关联商品和素材，每张反馈关联这次任务；将它们分开才能避免创意覆盖商品资料、改任务牵动旧图片、把一张评价当成整批判断。

> 标记说明：
>
> - **运营常用**：日常做图时经常要看或填。
> - **资料维护**：商品/素材管理员维护。
> - **自动/系统**：通常由公式、飞书工作流或系统写。
> - **当前不必填**：字段保留，但当前 MVP 主链不依赖。

### 商品库（10字段）

商品库回答的是：**“这个商品的真实身份是什么？”**

| 字段 | 谁维护 | 作用 | 怎么用 |
|---|---|---|---|
| 品牌与货号 | 自动/系统 | 商品主显示名 | 自动把「品牌 + 货号」拼起来。不要再手工维护第二套商品编号。 |
| 品牌 | 资料维护 | 品牌事实 | 填真实品牌，例如 UNIQLO。 |
| 货号 | 资料维护 | SKU/款式识别 | 填真实货号。注意：款式货号不一定等于颜色尺码级 SKU。 |
| 商品名称 | 资料维护 | 人能读懂的商品名 | 写真实商品名称，帮助运营识别。 |
| 品类 | 资料维护 | 当前商品属于哪类 | 当前选项：鞋 / 服装。用于区分不同商品边界。 |
| 核心卖点 | 资料维护 | 商品已确认的卖点 | 只写有真实依据的内容。不要让 AI 自己编材料、功能、性能。 |
| 禁改项 | 资料维护 | AI 绝对不能随便改的东西 | 例如颜色、原标记、人物、姿势、商品结构、现有版式关系等。是 Prompt Composer 的重要边界。 |
| 主图参考 | 资料维护 | 指向素材库中的主要参考图 | 关联素材库，不在商品表重复存同一份图片。 |
| 商品状态 | 资料维护 | 决定能不能进入正式生图 | 待确认 = 还不能放心用；可用 = 可以进入工作流；停用 = 暂停使用。Prompt 工作流要求商品可用。 |
| 备注 | 资料维护 | 其他不适合放正式字段的信息 | 可记录人工说明，但不要把关键商品事实只藏在备注里。 |

#### 商品库最重要的原则

**商品事实是最高优先级。** 创意不能覆盖商品事实。

### 素材库（11字段）

素材库回答的是：**“这次 AI 到底能看到哪些真实视觉证据？”**

| 字段 | 谁维护 | 作用 | 怎么用 |
|---|---|---|---|
| 素材名称 | 资料维护 | 人能快速识别素材 | 建议包含货号、颜色、视角，例如“488726 09黑色 模特正面”。 |
| 关联商品 | 资料维护 | 说明这张素材属于哪个商品 | 必须和真实商品对应。任务选错商品/素材组合时，工作流会停止。 |
| 素材类型 | 资料维护 | 说明图片是什么角色 | 商品原图 / 商品细节 / 场景参考 / 排版参考。不同角色不能混用。 |
| 附件 | 资料维护 | 真正要上传给 ChatGPT 的图片文件 | 当前正式流程使用这里的真实文件。 |
| 素材来源 | 资料维护 | 这张图片从哪里来 | 记录官方、公司资料等真实来源。 |
| 视角与用途 | 资料维护 | 这张图能证明什么、适合干什么 | 例如“正面穿着图，仅适合换环境”“侧面+上视组合，不能推断鞋底后跟”。 |
| 场景标签 | 当前不必填 | 给未来检索素材用 | 当前主链没有依赖，没有稳定标签体系时可以留空。 |
| 风格标签 | 当前不必填 | 给未来按风格筛选素材用 | 当前主链没有依赖。 |
| 渠道标签 | 资料维护/可选 | 说明素材适合哪些渠道 | 当前有拼多多、天猫超市。不是商品身份本身。 |
| 允许用于生图 | 资料维护 | 最重要的授权门 | 勾选才表示这张素材允许真正进入生图工具。当前工作流会检查。 |
| 素材说明 | 资料维护 | 记录颜色、可见结构、限制、特殊说明 | 人工确认内容优先。AI 建议不能覆盖人工确认事实。 |

#### “允许用于生图”不等于“允许公开”

一张图可以允许公司内部拿去生成，但不代表它可以被公开上传到 GitHub、作品集或公开文档。

### 提示词组件库（8字段）

提示词组件库回答的是：**“我们过去积累过哪些创作知识、保护规则和提示方法？”**

当前飞书主流程**不读取这 26 个组件**。它们保留为知识资产，不要求一线运营手工选择。

| 字段 | 谁维护 | 作用 | 怎么用 |
|---|---|---|---|
| 组件名称 | 维护者 | 给组件一个可读名字 | 例如“拼多多商品展示”“保留原标记”等。 |
| 组件类型 | 维护者 | 组件属于哪一类 | 渠道 / 图片功能 / 场景 / 风格 / 构图 / 光线 / 商品保护 / 限制。 |
| 组件内容 | 维护者 | 真正的提示知识 | 记录可复用的创作方法或规则。 |
| 适用渠道 | 维护者 | 哪些渠道适用 | 当前拼多多 / 天猫超市。 |
| 适用品类 | 维护者 | 哪些商品类型适用 | 当前鞋 / 服装。 |
| 风险备注 | 维护者 | 这个组件什么时候容易出问题 | 比如可能过度约束、可能引导未知角度。 |
| 是否启用 | 维护者 | 当前是否保留为有效知识 | 停用后不要当现役知识。 |
| 备注 | 维护者 | 补充说明 | 存来源、使用注意等。 |

#### 为什么组件库当前不进入主链

因为 MVP 优先证明：

```text
商品事实 + 素材事实 + 图片功能 + 用户想法
```

是否已经能得到可用Prompt。

没有必要为了“知识库看起来完整”，再把 26 条全部塞回 AI 上下文。

### 生图任务（17字段）

生图任务回答的是：**“这一次具体要做什么？”**

这是运营最常用的表。

| 字段 | 谁写 | 作用 | 怎么用 |
|---|---|---|---|
| 任务名称 | 运营常用 | 这次任务的人类可读名字 | 请保持唯一。Stage D 自动完成会用唯一任务定位做保护。 |
| 商品 | 运营常用 | 关联真实商品 | 必填。只选一个明确商品。 |
| 操作人 | 默认当前用户/运营确认 | 记录是谁建/做这次任务 | 配置默认当前用户，提交时确认没有选错；不等于创建人或全部参与人。 |
| 渠道 | 运营常用 | 图片最终面向哪里 | 当前：拼多多 / 天猫超市。 |
| 图片功能 | 运营常用 | 这次图片主要解决什么 | 商品看清楚 / 穿搭换环境 / 版式有设计感。 |
| 所处版面 | 当前不必填 | 更细的页面位置说明 | 当前 Prompt 主链不依赖；有明确运营需要时再填。 |
| 场景 | 当前不必填 | 手工补充明确场景 | 当前主链更依赖「自由补充想法」；无需为了填满字段而硬写。 |
| 风格 | 当前不必填 | 手工补充风格方向 | 同上。 |
| 目标图片数量 | 运营常用 | 想拿到几张候选 | 默认 3；当前 Stage D 也围绕 A/B/C 三张设计。 |
| 选择素材 | 运营常用 | 本次真正要给 AI 的素材 | 必填。必须来自当前商品且允许生图。 |
| 选择提示词组件 | 当前不必填 | 历史/未来用于明确选知识组件 | 当前原生 Prompt Composer 不读取，运营不用手选。 |
| 自由补充想法 | 运营常用 | 运营自己的一句话创作要求 | 例如“背景更浅”“更克制零售”“不要抢主体”。冲突时商品事实优先。 |
| 智能提示词草稿 | 自动/系统 | 飞书原生 AI 生成的可变化 Prompt | 状态待准备且输入齐全时自动写入。草稿可以重做。 |
| 最终提示词快照 | 运营确认 | 保存实际送进 ChatGPT 的完整 Prompt | 真正生成完成后再冻结。已有快照不要覆盖。 |
| 任务状态 | 人+自动 | 说明当前走到哪一步 | 待准备 / 待生成 / 待回传 / 待评价 / 已完成 / 已取消。 |
| 创建时间 | 自动/系统 | 创建记录的时间 | 自动生成。 |
| 三图回填 | 运营常用按钮 | Stage D 新增的 UX 按钮 | 待回传时点击“建立ABC反馈”，自动预建三条已命名、已关联记录。 |

#### 任务状态怎么理解

**待准备**  
输入正在准备，或需要 AI 重新生成 Prompt。

**待生成**  
Prompt 已经准备好，等人去 ChatGPT 生图。

**待回传**  
真实生图已经完成，Prompt 已冻结，等把 A/B/C 回飞书。

**待评价**  
兼容旧流程/中间流程使用。Stage D 新流程里不一定需要人为手动经过它。

**已完成**  
三张结果已经回填并评价齐全。Stage D 可以自动完成。

**已取消**  
这次任务明确不做了。

---

### 成图与反馈（7字段）

成图与反馈回答的是：**“这一张具体图片怎么样？”**

这里坚持：**一张图一条记录。**

| 字段 | 谁写 | 作用 | 怎么用 |
|---|---|---|---|
| 图片名称 | 自动/运营 | 一眼知道是哪张图 | Stage D 可自动预建 A/B/C 名称。 |
| 关联任务 | 自动/运营 | 说明这张图属于哪次任务 | Stage D 自动关联当前任务，不需要重复选三次。 |
| 图片附件 | 运营常用 | 真正的生成结果 | A/B/C 分别上传各自独立图片。 |
| 结果 | 用户本人 | 最终采用还是淘汰 | 只有人来选。未评留空，空不等于淘汰。 |
| 问题标签 | 可选 | 以后统计常见问题 | 当前没有稳定选项，没必要硬填。 |
| 喜欢标签 | 可选 | 以后统计常见优点 | 当前没有稳定选项，没必要硬填。 |
| 一句话备注 | 可选 | 记录为什么采用/淘汰 | 尽量用真实判断。委托代拟时要标明是代拟。 |

#### 为什么必须“一图一条”

因为 A/B/C 可能有完全不同的结果：

```text
A 采用
B 淘汰
C 采用
```

如果三张塞在一个单元格里，就没法准确记录每张的判断，也不方便以后统计。

---

### 周度总结（12字段）

周度总结回答的是：**“这一周总体发生了什么？”**

当前表保留，但正式自动周报还没有部署。

| 字段 | 谁写 | 作用 | 怎么用 |
|---|---|---|---|
| 周编号 | 未来运营/自动 | 哪一周 | 例如 2026-W41。 |
| 开始日期 | 未来运营/自动 | 统计区间开始 | 必须有明确时间范围。 |
| 结束日期 | 未来运营/自动 | 统计区间结束 | 同上。 |
| 任务数 | 未来自动/人工 | 本周有多少任务 | 先从真实记录计算。 |
| 已回传图片数 | 未来自动/人工 | 真正回到反馈表的图片数量 | 不拿“理论生成数”冒充。 |
| 已评价图片数 | 未来自动/人工 | 有采用/淘汰的图片数 | 未评的不算。 |
| 采用图片数 | 未来自动/人工 | 被人工采用的图片数 | 只统计真实评价。 |
| 采用率 | 未来自动 | 采用数 ÷ 已评价数 | 分母为 0 时留空，不编造 0%。 |
| 高频标签 | 未来可选 | 一周常见问题/喜欢点 | 等标签体系真实稳定后再用。 |
| 典型图片 | 未来可选 | 指向代表性成图 | 关联成图与反馈。 |
| 智能周度总结 | 未来 AI | 把已经算好的事实写成人话 | AI 不自己猜数字。当前未部署。 |
| 人工补充 | 运营/负责人 | 加上业务解释 | 写 AI/统计看不到的真实背景。 |

#### 周报的正确顺序

应该是：

```text
先确定时间范围
↓
程序/表格算真实数字
↓
再把真实数字 + 人工反馈交给 AI 总结
```

不应该让 AI 自己“看起来像对”地猜统计。

<a id="principles"></a>
## 四、为什么这样设计

### 商品事实先于创意

商品事实只来自商品库与选择素材，禁改项优先。AI设计场景、背景、版式、留白、光线与视觉语言，不改颜色、Logo/原标记、人物姿势与已见结构，不猜未知角度、材质、性能、参数或认证。用户想法与事实冲突时保留事实。

一张正面服装图不证明背面，一张侧面/上视鞋图不证明独立鞋底、后跟、内部或穿着效果。生成得合理仍可能是猜的；AI建议不能回写成为正式商品事实。

### 草稿可变，快照留证

草稿可以随任务想法重新生成；最终快照解释“这次真正用了什么文字”，应与实际发送内容一致并保留。快照不是ChatGPT内部指令，不代表后续全部聊天。采用/淘汰评价的是图片，不能仅凭结果把成败归因给某个组件。

### V1教训是验证顺序

早期先做Runtime、Runner、恢复、审核与自动合成，工程可靠性提高，却暴露贴纸感、光影不自然和使用复杂。可靠性本身有价值，问题是创作方法尚未证明前先建重系统。V2保留核验、历史保护、未知状态先读回的经验，先证明真实图片和人工反馈链路。

这不是对Codex或某模型能力的普遍判决。现在Codex负责开发维护，ChatGPT网页负责生成与连续调整；运营表达意图，人确认商品事实和最终图片判断。

### 自动流程与人工判断各有责任

确定的重复动作适合自动化：查记录、授权与匹配检查、建ABC、关联、状态判断。原生AI自动写Prompt属于概率性创作，仍可能写错，不因自动执行就称其确定。图片生成与采用/淘汰保持人工参与。

Stage D用按钮和画册减少重复，未增加新业务表或前端。24→15是同一口径的关键动作比较，不是鼠标总数、用时测试或工时节省比例；仍需三次上传、筛选任务一次、逐张开详情评价。

<a id="workflow"></a>
## 五、状态与原生工作流

| 状态 | 意义 | 谁推进 |
|---|---|---|
| 待准备 | 输入准备或要求重做Prompt，最终快照须空 | 人填任务；原生Composer校验 |
| 待生成 | 草稿完成，等网页生图 | Composer成功只写草稿与该状态 |
| 待回传 | 已真实生图，实际Prompt已冻结 | 人确认并修改 |
| 待评价 | 兼容旧中间状态；Stage D无需必经 | 已有流程可保留 |
| 已完成 | 三条附件和本人评价齐全 | Stage D非AI工作流只改状态 |
| 已取消 | 明确放弃本任务 | 人确认，不改旧快照/评价 |

### Prompt Composer：五步保持原样

| 节点 | 条件与动作 |
|---|---|
| 触发 | 商品、渠道、图片功能、选择素材非空，待准备，最终快照为空 |
| 查商品 | 商品状态可用，读取名称、品类、卖点、禁改项、状态、货号 |
| 查素材 | 选择素材允许生图、关联商品匹配且附件非空；读取名称、视角用途、说明、授权、关联商品 |
| 原生AI生成文本 | 输入商品/素材资料与任务想法、渠道、功能、数量；输出三个方向和完整中文Prompt |
| 更新当前任务 | AI成功后只写完整草稿与待生成；不写最终快照、商品或反馈 |

查无合格记录或AI失败时后续停止，保持待准备，不能把半成品写为正式草稿。草稿字段可能留有上一轮内容，运营须结合这轮状态核对。当前不读取26组件，不调用外部DeepSeek HTTP API，不使用自己的API Key。

### 三图建立：六节点非AI工作流

按钮触发（待回传）→查同任务已有反馈→仅0条时进入真分支→分别创建A/B/C。关联字段动态引用当前真实任务，名称自动带方向。三条是顺序创建，已有部分时不会补建；异常先读回，不盲目再次点击。

### 三图完成：六节点非AI工作流

反馈新增/修改且结果非空→查同任务全部反馈→查附件和结果非空反馈→查唯一任务→条件判断→只更新任务状态。

完成门：全部反馈恰好3、有附件且有结果恰好3、匹配任务恰好1、任务在待回传或待评价。任务查找当前采用关联任务显示名称匹配任务名称，需唯一；最终更新查找到的真实记录。重名或不齐全会停住，不随机选任务。系统只检查附件与结果非空，**独立三图、商品正确、评价来自本人仍由人核验**。

不是定时扫描，不会主动补扫所有旧反馈，也不回退已完成任务。先评价后上传等非标准顺序未经真实验收，不能把本手册当作自动修复承诺。

## 六、已验证与未验证

| 范围 | 已有证据 | 不能扩大成什么结论 |
|---|---|---|
| 阶段A | 两款真实任务得到原生AI完整Prompt与待生成 | 所有商品、所有Prompt都保真 |
| 阶段B | 两款各3张独立图，实际Prompt冻结；网页补生成后取得齐全结果 | 一次调用稳定出3张 |

| 33项离线回归 | 历史保护、输入规则与传输等对应逻辑通过 | 当前飞书全部节点、网页生图或未来效果已覆盖 |

模型与额度按验收日期看。阶段A查看的原生节点未显示模型名或选择入口，不能说底层就是DeepSeek。阶段A显示自动化免费赠送200次、已用8次；Stage D新增非AI运行4次，未再核验最新权益余额。旧的“剩余192次”不是实时额度，也没有据此证明永久免费。

26组件是保留资产，正式Composer不读；智能周度总结字段保留，正式周报未部署；创意建议和图片检查实验质量不足，两列已备份删除；AI推荐、自动生图队列、外部模型API、Runtime/Runner未启用。未来若做周度汇总，先定时间范围、算真实数字，再让AI组织文字，未评价或分母0不编造统计。

当前证据支持小范围MVP闭环，不支持转化提升、毛利提升、生产上线、大规模稳定或所有品类适用。第三款仍待素材。

## 七、维护与公开边界

### 资料正本与更新

此手册放在项目`docs/`，README与MAP提供入口。操作速记给日常步骤，手册给完整说明，STATUS给带范围的真实验收；历史领域模型、ADR说明关系与当时取舍，不把过时实现注记当当前运营入口。

工作流定义在飞书，公开克隆不带私有Base或业务身份。发生文档与实际行为冲突时，维护者核对最新真实验收与STATUS后同步速记、流程与手册；不凭描述自行改商品、历史快照或反馈。README架构每次实际流程变化重新生成图片，保持事实正确，不退回Mermaid。本次没有改变流程，沿用Stage D已核实配图。

### 生成权限与公开权限分开

允许用于生图不等于允许public GitHub或公开作品集。原图、业务生成图、私有截图、真实飞书ID与地址、Key和完整内部证据均不公开。经验包留在被忽略的内部目录；公开手册只说明方法和已核验边界。

### legacy代码与验证

原Python为**legacy / validation only**，用于历史回归、对账与规则证据，不参与日常Prompt生成。两个`.command`日常入口已退出。运营用飞书和ChatGPT，维护者可以在开发环境跑现有测试：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

测试通过不替代飞书与ChatGPT真实验收。远端写入留痕，超时或部分成功先读回，不盲目重发；沿用已有身份，不擅自安装或重新登录。
