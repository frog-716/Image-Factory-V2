# Image Factory V2

**飞书写需求，AI写Prompt，ChatGPT出图，回飞书人工选图。**

真实商品事实 · 已批准原图 · 原生AI编写Prompt · 三个创意方向 · 人工判断

这个项目来自一次产品纠偏：V1先建设了自动化流水线，真实试产却暴露出商品失真、场景融合差和使用门槛高的问题。V2保留素材核验与可靠性经验，让运营在熟悉的网页里创作，把Codex放回开发维护的位置。

> **MVP完整闭环 PASS。** 两款真实任务已完成阶段A/B/C：六张独立结果回飞书、正确关联原任务、用户本人采用/淘汰，两条任务均已完成。结果见[当前状态](docs/STATUS.md)。

## 一次任务怎么走

当前已验收的完整主流程：

```mermaid
flowchart LR
    A[飞书任务] --> B[AI Prompt]
    B --> C[ChatGPT生图]
    C --> D[飞书选图与反馈]
    classDef prepare fill:#edf5ff,stroke:#2475ed,color:#132f50;
    classDef finish fill:#e8f8f4,stroke:#169d91,color:#123e3a;
    class A,B prepare;
    class C,D finish;
```

AI草稿自动写回；ChatGPT网页生图、最终Prompt冻结、图片回传和人工评价由人操作。状态依次为：待准备 → 待生成 → 待回传 → 待评价 → 已完成。

其中，飞书 Prompt Composer 工作流只有五步：触发、查找关联商品、查找选择素材、AI生成文本、更新当前任务。商品需可用，素材需获准并属于当前商品；找不到合格记录就停止。最后一个节点只写草稿和任务状态，保留最终快照。当前不读取26组件，不调用外部DeepSeek HTTP API，不使用API Key。

ChatGPT可能把多个方向放进一张拼图，也可能只完成部分。数量说明已维护为“3张独立图片，A/B/C各一张，不要拼图、分栏或合在同一画布”；不足时在同一对话继续完成缺少方向。不能把一张三栏拼图当三张独立候选。

## 运营只需要做什么

在飞书“生图任务”填商品、渠道、图片功能、已批准素材，补一句自己的想法，目标数量通常是3。图片功能固定单选：**商品看清楚 / 穿搭换环境 / 版式有设计感**。

完整填写后让任务进入“待准备”，同一任务会自动出现完整中文 Prompt 和“待生成”状态。运营不用理解或选择26个底层组件。操作说明见[一页速记](docs/运营使用速记.md)和[使用流程](docs/使用流程.md)。

打开该任务选择素材的附件，在ChatGPT网页新开独立对话，上传真实原图并原样粘贴完整草稿。取得三张独立候选后，对照原图检查明显跑偏，保存图片；把实际使用的完整Prompt复制到最终提示词快照，确认一致，再改为“待回传”。

回到“成图与反馈”，每张图新增一条记录，上传对应图片并关联同一本轮任务；三张都回填后改“待评价”。用户本人逐张决定采用/淘汰，只记录真实原因；全部评价后任务才改为“已完成”。已有快照和旧反馈不覆盖。

两个旧启动器已删除，原有 Python 留作 **legacy / validation only**。日常不再要求 Terminal、`.command`、Finder、ZIP、本地任务ID或本地 Prompt 拼装。

## 商品事实与创意的边界

商品事实只来自商品库与选择素材。禁改项优先；创意差异来自场景、版式、构图、光线、色彩和视觉语言。不得改变商品颜色或原标记，不猜未知鞋底、后跟、内部、穿着角度、材质、性能或参数。用户想法与事实冲突时保留事实。

原图与生成图、真实飞书坐标、内部回执和Key均不进入公开仓。阶段B逐张检查未见明显商品跑偏，仍不能凭两个样本或离线测试宣称所有AI输出保真。

## 开发与历史验证

原 Python 能力用于维护、回归和历史对账，不是正式运营入口。公开测试使用独立合成数据，无需业务图片、飞书身份或模型Key：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

原生运行定义保存在飞书，真实坐标和完整运行证据仅在被忽略的私有目录；公开克隆不附带业务Base。维护脚本不参与日常Prompt生成。

## 从真实试错得到什么

- 组合商品原图能做限定视角的展示，不能证明未知鞋底、后跟或穿着角度。
- 三张候选应有明显设计差异；保护词不能代替逐张对照原图。
- 服装背景应服务服装，环境元素多不等于展示更好。
- 六表模型保留，运营不需要理解底层组件或寻找本地文件。

完整判断见[案例复盘](docs/案例复盘.md)和[经验与教训](docs/经验与教训.md)。案例图未经公开授权，不上传。
